# Rules: the non-negotiables

These hold in every round. A reviewer treats a breach as at least Important. Where a rule has a decision id, the
detail is in `docs/decisions.md`.

## Owner data and servers (G0, G3–G6)

- Tests talk only to fakes or the **local dev stack** on `127.0.0.1`. The integration-test scripts refuse anything
  else. Never point a test, script or agent at a real server.
- **Never delete or modify the owner's data.** Magpie only undoes what its own ledger says it did; an artist,
  album, profile or file the owner had is never changed.
- Diagnosis on a real server is **read-only GETs, with the owner's leave**. Never log in to Aurral on the owner's
  behalf.
- **Never write a real server address, hostname, IP, username, password, API key or token** into code, tests, docs,
  commit messages or logs. Use `music.example`, `music.example.com`, `nas.local`, `homeserver`, `100.64.x.x`,
  `192.168.1.x`, usernames like `jordan`, keys like `test-key`.

## Lidarr writes (G1, M6, FM1)

- Every write goes through **`LidarrWriteGate`** (`Packages/MagpieKit/Sources/LidarrKit/WriteGate.swift`): a
  never-call list, then an exact allow-list. The connection's `send` is `fileprivate`. "Allow Magpie to change Lidarr"
  is **off by default**.
- Deletes, moves and artist edits are **confined by the ledger** (`WriteConfinement.swift`): only what Magpie created
  or monitored, inside the Finds folder where it applies, re-read fresh right before sending (G3, G4).
- **Persist before every write (M6).** If the save fails, nothing is sent; the step waits.
- After a lost answer, **prove again** from a fresh read before sending anything again.
- **When in doubt, don't write.** An unclear state waits or asks the owner; it never guesses.
- A new write shape, command or Aurral route must be **pinned in `scripts/check-writes.sh`**, and
  `check-writes-selftest.sh` must still catch every planted bypass.
- The owner's profiles and settings are never modified; Magpie makes its own (`Magpie Finds`, `Magpie Finds Extras`,
  `Magpie Lossless`…) once, through the gate, and refuses a same-named profile set up differently (G5).

## Privacy and network

- **No direct calls to Deezer or Apple hosts** (plan decision 11): `MagpieCore/RefusedMediaHosts.swift` is the only
  place their names may appear in product code, and `check-writes.sh` enforces it. Previews and outside pictures come
  through the owner's Aurral server.
- Aurral calls go only to the exact routes in `AurralRoute`.
- Credentials and tokens live in the **Keychain** only. Logs and the change log go through `Redactor`/`Log.request`.
- Credentials are never sent over plain http to a public host without the **consent gate**.
- **Finds are never scrobbled** (D29), and that check fails closed.
- Tests never reach the public internet. Live tests that do (e.g. `LiveSongMatchIT`) run only with an explicit
  `MAGPIE_LIVE=1` and the owner's leave.

## UI copy and design

- Plain and warm, about music, never about services (`docs/storyboard/design-language.md` §5). "Lidarr",
  "Navidrome", "Aurral" appear only in Settings where a connection must be named. Never mention Soulseek, P2P,
  torrents or YouTube.
- Use the glossary (`docs/reviews/ux-appraisal-round-11.md` §9): Try, Keep, Not for me, Finds, Favourite, …
- British spelling: Favourite, colour, customisation. Nothing region-specific.
- Copy specified in a plan is used verbatim.
- **No dead buttons**: in each of the four setups (Navidrome alone; + Lidarr; + Aurral; all), a feature works, is
  hidden, or says why.

## Accessibility (D3, D12, D15)

- State is always **text plus an SF Symbol**, never colour or shape alone.
- Dynamic Type at every size, 44 pt targets, VoiceOver labels and named actions (e.g. Move up / Move down), Reduce
  Motion respected.
- CarPlay: template depth limits; copy describes, never instructs.

## Code

- Swift 6 language mode; `@MainActor @Observable AppModel`; actors for runners and stores. iOS-only APIs behind
  `#if os(iOS)` so the package builds and tests on macOS.
- **New work goes in new files** (`AppModel+X.swift`, `RequestRunner+X.swift`); big types get hook lines only.
- Follow the surrounding code's naming, structure and comment density. Doc comments explain *why* and cite the round
  and decision (`/// Round 19 (owner, …): … (D157)`).
- No `try!`, `as!`, force unwraps of server data or trapping conversions (`Int(exactly:)`, bounded loops and sizes).
- Never hand-edit `Magpie.xcodeproj` (generated by XcodeGen from `project.yml`).
- When a protocol gains a requirement, update every fake (`MagpieTestSupport`, the harnesses).

## Tests

- Swift Testing (`import Testing`, `#expect`/`#require`) for package and hosted tests; XCTest only for UI tests.
- **Tests assert**: every test has real expectations. Write the failing test first and keep its output; never claim
  RED you didn't see.
- No sleeps in unit tests: drive time with the test clock, or poll with a deadline.
- A protocol fake, a stub server or the `RunnerHarness`/`FakeLidarr` instead of the network.

## Working with others

- Implementers don't dispatch subagents, merge, tag, archive, upload or push; reviewers don't edit.
- If a permission is refused, report it; never work around it.
- Say plainly what wasn't run, what failed and what is left.
